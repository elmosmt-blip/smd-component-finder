# smd-component-finder

Инструмент идентификации SMD-компонентов по маркировке, номеру детали или снимку с камеры.
Работает полностью в браузере: поиск, OCR и база данных — локально, без отправки данных на сервер.

Репозиторий появился как результат разбора эталонного инструмента
[smtinsider.com/finder](https://www.smtinsider.com/finder). Разбор — в **[ANALYSIS.md](ANALYSIS.md)**:
что там сделано хорошо, какие узкие места и что именно переделано здесь.

## Быстрый старт

Открыть локально (без сборки и зависимостей):

```bash
# любой статический сервер, например:
python3 -m http.server 8000
# затем http://localhost:8000
```

Сервер нужен только из соображений удобства: файлы static, сборка не требуется.
Поиск работает и при открытии `index.html` напрямую с диска, а вот камера
потребует `https://` или `localhost` — это ограничение браузера, а не кода.


## Как это работает

**Поиск устойчив к ошибкам распознавания** — это ключевое отличие. Обычный поиск
по подстроке ломается там, где OCR ошибся всего в одном символе:

| Запрос | Что происходит |
|---|---|
| `A7` | оба кандидата: **BAV99** (92 %) и 1N4148W (86 %). Код `A7` у 1N4148W помечен как ненадёжный, поэтому BAV99 выше |
| `A7` + фильтр `SOD-123` | первым становится **1N4148W** — корпус снял неоднозначность |
| `7O2` | находится **2N7002**: замена `O`→`0` стоит 0.2, а не 1.0, и это трактуется как ошибка OCR |
| `1AM` | находится **MMBT3904**: `M` распознано как код партии и отсечено |
| `662K` | **XC6206P332MR** |

Оценка собирается из явных слагаемых, и каждое показывается пользователю в
`Match reasons`: точное совпадение, штраф за короткий код, бонус за совпадение
корпуса, надёжность конкретного кода в базе.

**OCR** не отправляет картинку в Tesseract «как есть». Кадр кадрируется,
бинаризуется порогом Оцу, прогоняется с инверсией (лазерная маркировка — это
светлый текст на тёмном компаунде, а движки ждут обратного) и с локальным
порогом против бликов. Затем каждый вариант распознавания прогоняется через
поиск, и результат показывается в виде «распознано → найдено в базе».

## Своя база данных

Встроенные 104 записи — демонстрационный набор. Рабочая база подключается так:

```bash
node tools/import_dataset.mjs markings.csv --merge
# → data/extra-parts.json
```

Затем в интерфейсе: **Import CSV / JSON**. Импортированные записи сохраняются
в `localStorage` вашего браузера.

Формат CSV (разделитель `,` или `;` определяется автоматически):

```
part,mfr,pkg,type,desc,v,i,pins,markings,conf,note
```

- `part`, `pkg` — обязательны;
- `markings` — несколько кодов через `|`;
- `conf` — `high` (код устойчив между производителями) / `med` / `low`
  (код конкретного завода, есть конфликты).

Подробности о формате и назначении полей — в `data/README.md`.

> **Маркировка SMD не стандартизована.** Один и тот же код у разных
> производителей означает разные детали. Любой результат нужно подтверждать
> по datasheet перед заменой компонента.

## Тесты

```bash
node tools/test-matcher.js        # ядро поиска: 30 проверок
npm install && npm test           # + smoke-тест интерфейса в jsdom: 24 проверки
```

## Ограничения

- База — seed-набор, а не авторитетный справочник.
- OCR-движок (tesseract.js) подгружается с CDN при первом использовании;
  для работы без интернета положите его рядом.
- Тестировалось в Node 22 и jsdom; на реальных макрофото камеры предобработка
  не проверялась.
