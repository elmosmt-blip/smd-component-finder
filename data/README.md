# Данные: формат и соглашения

## Файлы

| Файл | Назначение |
|---|---|
| `assets/js/data.js` | рабочая база, загружаемая страницей (`SMD_DB` + `SMD_PACKAGES`) |
| `sample-import.csv` | пример внешнего файла для импорта |
| `extra-parts.json` | результат работы `tools/import_dataset.mjs` (в git не хранится) |

## Поля записи

| Поле | Обяз. | Смысл |
|---|---|---|
| `part` | да | номер детали |
| `mfr` | нет | производитель |
| `pkg` | да | корпус — **должен существовать в `SMD_PACKAGES`**, иначе фильтр по нему останется пустым |
| `type` | нет | тип/функция: `NPN BJT`, `N-MOSFET`, `Диод Шоттки`, `LDO`… |
| `desc` | нет | человекочитаемое описание |
| `v` | нет | напряжение (Vceo, Vds, Vrwm — по смыслу детали) |
| `i` | нет | ток или мощность |
| `pins` | нет | распиновка. Критична для замены: у SOT-23 она бывает разной |
| `markings` | нет | массив кодов. Строка или объект `{ c: 'A7', conf: 'low' }` |
| `conf` | нет | `high` / `med` / `low` — надёжность привязки «код → деталь» |
| `note` | нет | конфликты кодов, подделки, отличия цоколёвок |

## Что значат уровни `conf`

| Уровень | Когда ставить | Пример |
|---|---|---|
| `high` | маркировка совпадает с номером детали или общепринята у всех производителей | `M7`, `SS14`, `78M05`, `PC817`, `TP4056` |
| `med` | код широко известен, но есть варианты и исключения | `1A` = MMBT3904, `A7` = BAV99, `T4` = 1N4148W |
| `low` | код из таблицы конкретного производителя или заведомо конфликтный | `Z14` = BZX84C3V3 (только NXP), `AE` = SMAJ5.0A, `B` = RB751S-40 |

`low` — не значит «данные плохие». Это значит «инструмент обязан предупредить».

## Зачем `conf` на уровне кода, а не детали

У одной детали разные коды имеют разную ценность. Классический случай:

```js
{
  part: '1N4148W',
  markings: [{ c: 'T4', conf: 'med' }, { c: 'A7', conf: 'low' }]
}
```

Код `T4` действительно принадлежит 1N4148W, а `A7` у части заводов означает
совсем другую деталь — BAV99. Если хранить один `conf` на деталь, поиск по `A7`
поставит 1N4148W и BAV99 вровень и пользователь не получит подсказки.
Раздельная надёжность кодов снимает неоднозначность без ручных правил.

## Как добавить корпус

`SMD_PACKAGES` в `assets/js/data.js` — массив кортежей:

```js
['SOT-23', 'transistor', 3, '2.9 × 1.6', 'заметка по пайке и применению']
//  имя      семейство     выводы  размер мм   заметка
```

Семейство (`transistor`, `ic`, `diode`, `other`) используется поиском: если
выбран фильтр `SOD-123`, то `SOD-323` получит частичный бонус как «родственный
корпус», а `SOT-23` — штраф. Это лечит ситуацию, когда пользователь не уверен
в точном названии корпуса.
