## Шаг E1. Аудит таблиц (окно 1)

```bat
.venv\Scripts\python tools\rag\audit_tables.py --corpus C:\smd-corpus\pdf --limit 50 --parser pdfplumber --json audit2.json
```

Это главный шаг фазы. Он отвечает на вопрос «какие заголовки таблиц парсер
не узнаёт» — по ответу дополняется словарь, а он влияет на **все** будущие
карточки, а не только на эти 50 файлов.

`--parser pdfplumber` обязателен. С Docling прогон падает через 45 минут с
`0xC00000FD` (переполнение стека в torch) и теряет весь результат.

Ждать 30–60 минут. Не прерывай. Если всё-таки упадёт — `audit2.json` теперь
перезаписывается после каждого файла, поэтому пришли хотя бы его: в нём
будут данные по обработанной части.

## Шаг E3. Собрать карточки (после того, как E2 наберёт объём)

```bat
.venv\Scripts\python tools\rag\build_cards.py --corpus C:\smd-corpus\pdf --out data\cards --jobs 16 --no-shards
```

**Без `--rebuild`.** Без него команда только добавляет новые карточки к
существующим 14 459: файлы, разобранные раньше, пропускаются по SHA1.

`--rebuild` стирает базу *до* появления новых карточек. Именно так в фазе D
были потеряны 14 459 карточек (прогон D3 умер через 50 минут, оставив 56).

## Как присылать результаты: отдельная ветка

Копировать вывод в чат не нужно — агент на машине может пушить отчёты в
GitHub, а я их сам прочитаю. Правила простые, и все ради одного: **не
испортить мою ветку**.

1. **Своя ветка, не `arena/01a0568a-smd-component-finder`.**
   `git checkout -b reports/2026-09-04-d5` — я заберу её командой
   `git fetch origin reports/2026-09-04-d5` и прочитаю файлы, не трогая свою
   рабочую ветку.
2. **Только отчёты.** `audit2.json`, логи, `.md` с выводом. Код
   (`tools/`, `assets/`, `index.html`, `package.json`) не трогать вообще:
   там работаю я, и встречный коммит приведет к конфликту.
3. **Никаких баз, PDF и CSV.** `.gitignore` уже исключает `*.db`,
   `*.sqlite3` и `*.csv` — если `git status` перед коммитом показывает файл
   больше мегабайта, его туда не надо.
4. **Сообщи имя ветки.** Одной строкой: `ветка reports/2026-09-04-d5,
   файлы audit2.json, d5.log`.

Проверить, что пуш вообще возможен:

```bat
gh auth status
```

Если GitHub не авторизован — тогда просто вставляй вывод в чат, как раньше.

Команды целиком:

```bat
git checkout -b reports/2026-09-04-d5
git add audit2.json d5.log
git commit -m "D5: аудит таблиц, 50 файлов, pdfplumber"
git push -u origin reports/2026-09-04-d5
```

## Форма отчёта

Пришли одним сообщением, можно по ходу:

```
E0 git log:              <хэш и тема>
E1 аудит таблиц:         <весь вывод целиком, от "=" и до конца>
   или, если упал:       audit2.json (и код выхода)
E2 скачка:               файлов скачано / ГБ / сколько позиций в списке
E3 карточек в базе:      N (если запускал)
Ошибки:                  строки "! ...", если были
```

Вывод E1 вставляй целиком, не выборочно: нужны и частоты, и примеры строк.
